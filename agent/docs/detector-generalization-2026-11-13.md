# 탐지기 v1/v2 고정 후 합성 스트레스 검증

## 결론

**v8에서 관측한 ‘오경보 제거 + 이상 탐지 유지’를 일반적인 성능으로 확대할 수 없다.** v2는 짧은 정상 변동의 오경보를 줄이지만 짧은 실제 이상도 놓치며, 간헐적 이상을 상당히 늦게 탐지한다. 긴 정상 운전 조건 변경도 구분하지 못한다.

이는 학습 모델의 훈련 과적합을 측정한 실험이 아니라, **이미 본 데이터로 선택한 탐지 규칙의 일반화 한계**를 확인한 실험이다. 새 합성 자료에서도 일부 이득은 유지되므로 ‘v8에서만 동작한다’는 단정 역시 부정확하다. 현장 적용 성능은 아직 입증하지 못했다.

이번 검증에서는 운영 탐지기, 임계값, API, LangGraph, 우선순위를 변경하지 않았다. 새 결과를 본 뒤 탐지기를 다시 튜닝하지 않았다.

## 실험 설계

- v8 CSV나 정답 파일을 전혀 읽지 않는 별도 생성기를 사용했다.
- 28가지 시나리오 × 3가지 잡음 × 30개 시드 = **2,520회**. 정상 1,350회, 이상 1,170회.
- 잡음: 독립 정규 잡음 / 자기상관 AR(1), 계수 0.7 / 큰 이상값이 상대적으로 자주 발생하는 t(자유도 3) 잡음. t 잡음은 표준편차가 1이 되도록 조정했다. MAD 기준 척도는 정규 잡음과 다를 수 있다.
- 정상/이상 변화의 길이·크기·기울기·대상 센서·방향을 바꾸었다. 진폭은 생성기 기준 표준편차 단위이며 탐지기가 추정하는 robust Z와 정확히 같은 값은 아니다.
- 각 실행은 정상 기준 240분, 관측 60분, 변화 구간, 복귀 후 60분으로 구성했다. 간격은 1분이다.
- v1과 v2에 같은 입력을 주었다. 첫 240개 관측에서 각 탐지기가 정상 기준을 추정하는 기존 동작만 허용했다.
- 시작 전에 시나리오·시드·코드 SHA-256을 `manifest.json`으로 저장했고 종료 시 코드가 바뀌지 않았음을 검사했다.
- 외부 알람 입력은 모두 `NONE`. 기존 알람이 탐지 실패를 가려 주지 않게 했다.
- 실제 고장/정상 라벨은 평가에서만 사용한다. 에이전트나 외부 LLM은 호출하지 않는다.

정상 운영 변화라는 라벨은 **승인된 설정 변경·허용된 일시 변동이라는 가정**이다. 해당 변화가 실제 공장에서 정상이라는 실증 자료는 아니다. 이 가정은 센서만 보는 탐지기의 한계를 드러내기 위한 것이다.

## 전체 결과

| 지표 | v1 | v2 |
|---|---:|---:|
| 정상 실행 중 새 예고가 1회 이상 나온 실행 | 1,127/1,350 (83.5%) | 636/1,350 (47.1%) |
| 정상 실행에서 발생한 신규 예고 사건 수 | 1,507 | 639 |
| 이상 구간 안에 신규 예고를 낸 실행 | 1,050/1,170 (89.7%) | 974/1,170 (83.2%) |
| 두 탐지기 모두 성공한 실행 | 918 | 918 |
| v1은 성공했지만 v2는 놓친 실행 | — | 132 |
| v1은 놓쳤지만 v2는 성공한 실행 | — | 56 |
| 둘 다 성공한 실행의 v2 추가 지연 | — | 중앙값 2분, 최대 83분 |

**이 비율은 인위적으로 구성한 시험 집합 안의 비율이며 현장의 오경보율·고장 탐지율이 아니다.** 각 시나리오의 비중은 실제 발생 빈도가 아니다. 특히 정상 변화로 지정한 큰 설정 변경을 다수 포함한다.

오경보는 변화 구간뿐 아니라 기준 추정 이후의 전체 정상 실행을 세었다. 따라서 사전 잡음/복귀 후 꼬리에서 발생한 예고도 포함된다. 이상 탐지 성공은 이상 구간 안에 **새 사건이 열린 경우**만 센다. 이상 전 오경보가 계속 열린 상태이거나 복귀 후 늦게 예고된 경우에는 성공으로 인정하지 않았다.

## 정상 패턴별 결과

각 숫자는 정상 실행 중 1회 이상 예고한 실행 수다.

| 정상 시나리오 | 실행 수 | v1 | v2 |
|---|---:|---:|---:|
| 정상 잡음만 유지 | 90 | 31 | 1 |
| 1~3분 일시 변동 | 360 | 198 | 5 |
| 6분 일시 변동 | 180 | 180 | 40 |
| 9~15분 일시 변동 | 360 | 359 | 358 |
| 승인된 점진/계단 설정 변경, 60분 | 180 | 180 | 180 |
| 잡음 표준편차 2배 증가 | 90 | 89 | 46 |
| 서로 다른 센서가 번갈아 변동 | 90 | 90 | 6 |

짧은 변동과 센서 간 교대 변동 억제 효과는 새 자료에서도 나타났다. 그러나 6분 변동도 주변 잡음이 이탈 횟수에 합산되어 통과할 수 있다. 9분 이상 큰 변동은 지속 조건 자체를 만족하므로 거의 억제되지 않았다. **현재 방식은 정상/고장의 원인을 구분하는 모델이 아니라 편차와 지속성을 보는 탐지 규칙**이다.

## 이상 패턴별 결과

각 숫자는 실제 이상 구간 안에 새 예고를 낸 실행 수다.

| 이상 시나리오 | 실행 수 | v1 | v2 |
|---|---:|---:|---:|
| 60분 지속 편차, 3.5/5/8 SD | 270 | 252 | 269 |
| 느림/중간/빠른 점진 상승·하강 | 270 | 265 | 270 |
| **3분 실제 이상** | 90 | 31 | **0** |
| **6분 실제 이상** | 90 | 82 | **15** |
| 9분 실제 이상 | 90 | 81 | 90 |
| **3분 이상 / 3분 복귀 반복** | 90 | 86 | **60** |
| 7분 이상 / 3분 복귀 반복 | 90 | 83 | 90 |
| 주기적 진동 이상 | 90 | 84 | 90 |
| 3개 센서에 동시 3 SD 편차 | 90 | 86 | 90 |

몇 유형에서 v2의 사건 탐지 수가 더 높은 것은 주의해서 해석해야 한다. v1은 큰 이상값이 자주 나오는 정상 잡음에서 미리 오경보를 열고 유지하는 경우가 많았다. 이 경우 뒤에 실제 이상이 시작해도 ‘새 사건 탐지’로 인정하지 않았다. **v2가 원인을 더 잘 이해했거나 모든 점수 감도가 높아졌다는 뜻이 아니다.**

이를 확인하기 위해 이상 전 오경보가 없었던 독립 정규 잡음 조건만 따로 보았다.

| 독립 정규 잡음 조건 | v1 | v2 |
|---|---:|---:|
| 모든 이상 패턴 합계 | 363/390 | 318/390 |
| 5 SD 지속 이상 탐지 | 30/30 | 30/30 |
| 위 패턴 탐지 지연 중앙값 | 4분 | 6분 |
| 3분 이상 / 3분 복귀 탐지 | 30/30 | 16/30 |
| 위 패턴 성공 사례의 탐지 지연 중앙값 | 3분 | 35분 |

간헐적 이상의 최악 대응 쌍은 **v1 3분 → v2 86분**이었다. 실행 시드는 `20501126`, 대상은 진동 센서, 독립 정규 잡음이다. 최근 9개 중 7개 이탈 조건을 간헐적 패턴이 자주 만족하지 못하여 우연한 잡음이 조건을 채워 줄 때까지 지연된다.

## 조기 탐지 유지 여부

점진 이상 270개는 v2가 모두 구간 안에서 탐지했다. 다만 ‘조기’ 비교를 위해 사용한 기준은 **생성기의 잡음 없는 편차가 8 SD에 도달하는 가상 시각**이다. 실제 현장 경보나 v8의 14:15 알람이 아니다.

- 가상 기준 전 신규 탐지: v1 263/270 → v2 268/270.
- 성공 사례의 가상 선행 시간 중앙값: 22분 → 21분. 표본 구성이 달라 두 중앙값의 차이는 개별 지연의 중앙값과 다르다.
- 사전 오경보가 없는 독립 정규 잡음의 점진 이상 90개에서는 두 버전 모두 기준 전에 탐지했다.
- 이 조건의 느린 변화 선행 시간 중앙값은 54.5분 → 53.5분, 중간 변화는 19분 → 19분, 빠른 변화는 5분 → 5분이었다. 각각 30회다.
- 개별 점진 이상은 추가 지연이 생긴 사례도 있다. 모든 잡음 조건의 두 탐지기 공통 성공 265개에서 추가 지연 중앙값은 0분, 최대 19분이다.

따라서 **점진적으로 지속되는 이상에서는 조기 탐지가 대체로 유지되었지만, 짧거나 간헐적인 이상까지 유지되었다고 말할 수 없다.**

## 설계상 원인과 다음 결정

1. v2의 지속 조건은 정상 변동 억제와 실제 단기 이상 억제를 동시에 만든다. 단일 지속 조건으로 전 유형을 처리하는 설계를 그대로 확정하지 않는다.
2. 승인된 설정 변경과 고장이 똑같은 센서 편차를 만들면 센서 입력만으로 둘을 구분할 수 없다. 같은 시드·파형에 정상/이상 라벨만 달리 주었을 때 두 탐지기의 출력이 동일함을 테스트했다. 제품/레시피/운전 상태와 설정 변경 이력 등 **실제로 존재하는 맥락**이 필요하다.
3. 다음 개선 후보는 지속적 드리프트, 급격한 큰 편차, 간헐적 반복을 따로 평가하는 방식이다. 이는 아직 구현·검증하지 않은 제안이며, 현재 시험 결과에 맞춰 바로 규칙을 추가하고 일반화 성공이라고 주장하지 않는다.
4. 개발용 시나리오와 최종 평가용 패턴/시드/설비·기간을 미리 분리한다. 진짜 현장 자료나 독립적으로 만든 생성 자료의 평가는 별도로 필요하다.
5. 에이전트가 없어서 생긴 오류라고 결론 내릴 수 없다. 모델/도구에 없는 운전 맥락을 LLM이 추측하게 해서는 안 된다. 중간 MVP의 ‘예고 후 조사’ 에이전트는 이미 발생한 최초 예고 오경보를 소급해서 없애지 않는다.
6. 기존 센서 경보는 이 게이트를 우회한다. 하지만 기존 경보가 없는 짧은 실제 이상을 못 잡는 한계는 그대로 남으므로, 알람 우회가 탐지 성능의 대체 근거는 아니다.

## 재현과 산출물

저장소 루트에서:

```sh
../qfirst-local/.venv/bin/python agent/scripts/validate_detector_generalization.py
PYTHONPATH=agent ../qfirst-local/.venv/bin/python -m unittest discover -s agent/tests -v
```

- 코드: `agent/scripts/validate_detector_generalization.py`
- 사전 고정 조건/해시: `agent/var/generalization/manifest.json`
- 전체/유형/잡음별 집계와 개별 결과: `agent/var/generalization/results.json`
- 2,520회 개별 비교: `agent/var/generalization/trials.csv`
- 새 평가 유효성 테스트: `agent/tests/test_generalization_evaluation.py`
- 검증 당시 전체 테스트: **16개 통과**. 정답 미사용, 시드 재현, 미래 데이터 변경 불변, 사전 오경보/복귀 후 예고의 성공 처리 금지를 포함한다.
- `var/`는 Git 제외다. 데이터는 로컬에서만 생성·처리했다.

고정한 탐지기 SHA-256:

```text
v1 31b03df466e95cc5d3b14dfa346f654df13f6ffb74c699092f5b651dad5fb4a4
v2 9b96aa5cd18c9697459d9b06f95221b2788eb1658df6c55e0e57dc2e0714e662
```

이번 시험도 v8의 한계를 알고 설계한 합성 스트레스 시험이다. 최초 240개가 정상이고 안정적인 조건을 가정하며, 비정상 기준 추정·새 제품/금형·실제 센서 오류·현장 분포를 포괄하지 않는다. 성공률을 실운영 성능으로 제시하면 안 된다.
