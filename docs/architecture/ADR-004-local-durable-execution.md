# ADR-004: 로컬 LLM과 영속 조사 작업 실행

상태: 로컬 MVP 구현·검증 완료 · 2026-11-13

## 결정 범위

중간발표 MVP의 탐지기, 등급·순위 규칙, LangGraph 조사 범위는 유지한다.
탐지 성능 개선 및 최종 목표의 에이전트 판단 확장은 별도 검토한다.
외부 LLM API는 사용하지 않고 개발 PC의 Ollama(qwen3:4b)를 호출한다.

## 책임과 실행 흐름

1. Spring 수집·재생 모듈이 읽기 전용 v8 파일을 읽고 해당 재생 시각의 입력을 연결한다.
2. Python FastAPI의 `/detect`가 기존 탐지 결과를 반환한다. Spring이 품질 연결·등급·목록별 순위를 계산한다.
3. Spring은 화면 스냅샷, 판단 버전, 재생 요청의 멱등 응답, 신규 조사 작업을 PostgreSQL에 같은 트랜잭션으로 저장한다.
4. Spring 조사 워커가 DB 큐에서 작업을 선점해 Python `/investigations/run`을 호출한다. 사용자의 화면 요청과 별개인 실행 스레드에서 동작한다.
5. Python LangGraph가 필수 근거 조회 → 로컬 LLM 도구 선택 → 도구 실행 → 구조화·검증을 수행한다. 이 호출 자체는 HTTP 응답을 기다리지만 전체 업무는 영속 큐를 통한 비동기 실행이다.
6. 워커가 조사 결과를 DB에 저장한다. Spring 게시 모듈은 사건·기준 시각·근거 ID를 검증한 후 안내만 새 버전으로 게시한다. 등급·순위는 조사 결과로 변경하지 않는다.
7. React가 기존 API와 폴링으로 조사 상태·기본/구체화 안내를 표시한다.

## 왜 이 구조인가

- 메모리 큐 대신 PostgreSQL: 현재 처리량에서는 별도 브로커보다 운영 항목이 적고 판단 저장과 작업 등록을 원자적으로 묶을 수 있다.
- Spring이 큐 소유: 업무 사건 생성·중복 방지·게시 책임을 한곳에 둔다. Python은 조사 실행을 담당한다. Python의 예전 메모리 큐 엔드포인트는 Compose 모드에서 차단한다.
- 단일 조사 실행: 개발 PC Ollama의 동시 추론 부담을 제한한다. 큐에서 대기해도 기본 판단은 조회 가능하다.
- 로컬 LLM: 데이터와 추적 정보를 외부 LLM/추적 SaaS로 보내지 않는다. Compose의 host.docker.internal은 개발 PC를 가리킨다.
- 입력 파일 보존: 원본 CSV 내용과 해시를 DB에 보관하고, 다른 데이터셋으로 기존 판단을 잘못 복원하지 않도록 시작 시 일치 여부를 확인한다.

## 장애·중복 처리

- 작업 선점: PostgreSQL FOR UPDATE SKIP LOCKED.
- 실행 임대 210초, Python 실행 제한 150초, 내부 HTTP 읽기 제한 180초.
- 연결/서버 오류는 최대 3회 시도, 재시도 간격 5초. 검증 오류는 재시도하지 않는다.
- 워커 중단 시 임대 만료 후 다시 선점. 작업 ID 중복 등록 방지.
- 매 시도마다 토큰을 바꿔 이전 시도의 늦은 완료 쓰기를 거부한다. exactly-once 추론을 주장하지 않는다. 추론은 재실행될 수 있으며 도구는 읽기 전용이다.
- 예고에서 비상으로 전환된 사건은 새 조사 작업을 만든다. 이전 예고 조사 결과는 현재 비상 조사 안내를 덮어쓰지 않는다.
- DB 저장 실패 시 미확정 화면 상태를 되돌리고 쓰기 요청을 실패시킨다.
- 재시작 시 재생 시각·판단 버전·멱등 요청 응답을 복원한다. 완료 결과가 아직 게시되지 않았다면 다시 읽어 게시한다.

## MVP의 한계와 후속 작업

- Spring 단일 인스턴스만 지원한다. DB 세션 advisory lock으로 두 번째 소유자를 거부한다. 다중 인스턴스/고가용성 설계는 별도다.
- 시나리오 CSV 재생이며 실 MES·SCADA 연결이 아니다. Java/Python은 동일한 읽기 전용 데이터 볼륨을 사용한다. 일반화된 수집 어댑터와 공통 정규화 테이블은 후속 작업이다.
- DB의 입력 보관은 전체 CSV 원본 스냅샷이며, 이벤트 단위 정규화 적재가 아니다. 도구는 재생 시각으로 필터링한다.
- 실제 현장 점검 착수·결과 저장·이력 화면·자유 챗봇 API는 이번 변경에 포함하지 않는다.
- 체크포인트 JSON은 단일 보드 복구용이다. 판단 버전은 별도 append 테이블에도 보존한다. 이벤트 수가 커지면 증분 저장으로 전환한다.
- DB 백업·복구, 인증·권한, TLS, 모니터링, 운영 배포 하드닝은 완료되지 않았다. 현재 Compose는 루프백 포트만 공개하는 로컬 검증용이다.
- 최초 예고 시각과 오경보 수치는 기존 검증 결과를 유지하며 일반화 한계도 해결됐다고 간주하지 않는다.

## 확인한 결과

- Python 기존 테스트 16개 통과: 탐지 조건, 미래 데이터 차단, 근거 검증, 조사 실패 처리.
- 실제 PostgreSQL 별도 테스트 DB에서 5개 통과: 중복 등록/복원, 만료 임대와 이전 토큰 거부, 재시도 상한, 큐 등록 실패 시 판단 저장 롤백, 두 번째 Spring 소유자 거부.
- Docker 웹 프록시 경유 실제 재생 검증 통과: 14:00 → 14:05 → 14:15, LOT 집계, 비상 전환, Ollama 조사 완료, 기본/구체화 안내, 근거 ID, 순위 불변.
- Spring/Python 컨테이너 재시작 후 보드 전체 응답, 판단 버전, 조사 근거, 재생 멱등 응답 동일함을 확인.

이 검증은 아키텍처 연결·복구 검증이며 탐지 성능이나 실제 제조 현장 안전성 검증을 대신하지 않는다.
